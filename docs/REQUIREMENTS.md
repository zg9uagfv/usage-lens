# usage-lens 需求 v0.2（已定范围）

一句话：macOS 菜单栏常驻的配额看板，一眼看到 Codex / DeepSeek / Claude 现在用了多少、多久后重置。

参考形态：用户给的截图（菜单栏图标 + 点击弹面板 + provider tab + 每个窗口一条进度条 + 重置倒计时 + 刷新时间）。

## 已确认范围

| Provider | 展示内容 | 数据来源 | 状态 |
|---|---|---|---|
| Codex | 5h / 7d 已用百分比、重置时间、plan、今日 tokens | 本地日志 `event_msg.token_count.rate_limits` / `token_usage_record` | 可做，已实测 |
| DeepSeek | 余额（配置页可存 API key）+ 今日/窗口花费估算；**无窗口百分比** | `/user/balance` + 本地 `tokenUsage.totals` | 可做，余额需 key |
Antigravity / Grok / Claude：首版不做（用户明确排除）。

Claude 排除原因（2026-11-15 决定）：接口非官方、需读钥匙串凭据，而"只读不刷新"又会在 token 过期时长期显示陈旧值，收益不抵复杂度。调研结论留档在 `docs/RESEARCH_claude-usage.md`，将来要做时可直接接探针架构，App 侧不用改。

## 不做

- token 记账报表、按项目/模型归因、导出 CSV/PNG（原 v0.1 的 F/V 系列押后）
- 多账号切换、团队共享、云端服务
- 余额对账反推花费
- 读取、打印或落盘任何凭据（探针只允许"使用"，不允许"暴露"）

## 硬性约束（数据真实性）

1. 没有窗口概念的服务不许画百分比进度条；没有数据时显示「无数据」，不许显示 0%。
2. 服务端给的数和本地推导的数要能区分（`basis: server | local`）。
3. 拿不到就明示原因（`warnings`），不静默吞掉。
4. 只读本机数据，网络只请求官方域名。

## 界面要求

- 菜单栏图标常驻，标签显示当前最紧张的窗口（例 `Codex 5h 33%`）
- 点击弹 popover，provider tab 切换，tab 头显示账号 + 状态
- 每个窗口：名称、进度条、`已用 XX%`、`X 小时 Y 分后重置`
- 底部 `刷新` + `N 分钟前更新`
- 自动刷新 60 秒；失败保留上次值并灰化提示
- 可选登录后启动，默认关闭
- 深浅色跟随系统；字体和留白要有水准，截图能直接拿给别人看

# usage-lens · 需求清单 v0.1（待用户勾选）

目标：本机可视化 Codex 与 DeepSeek 的用量（tokens / 成本 / 会话 / 模型 / 项目），
一眼看出"钱烧在哪、哪次会话浪费了上下文"。

## 0. 已确认的数据事实（本机实测，2026-11-15）

| 来源 | 路径 | 可用字段 | 覆盖 |
|---|---|---|---|
| Codex | `~/.codex/sessions/**/*.jsonl` | `token_usage_record`：input / cached_input / output / reasoning / total；`turn_context`：model、cwd、effort；`session_meta`：provider、cli 版本 | 6 个 thread / 217 条用量记录 / 6 天 / 约 14.7M tokens |
| DeepSeek (DS Bot) | `~/.dsh/sessions/**/session.v4.jsonl.zstd`、`~/.dsh/storages/session_projcache/**` | `tokenUsage.totals`（缓存/未缓存输入、输出）、会话 cwd、时间 | 只有 11-15 装机之后的会话，历史为空 |

结论：Codex 侧数据够做完整时间序列；DeepSeek 侧先做"能接上、格式对"，历史量要等积累。
`zstd` 命令本机在 `/opt/homebrew/bin/zstd`，解压可用。

## 1. 功能项（F = 数据与计算，V = 视图，U = 体验，T = 技术）

| 编号 | 需求 | 验收标准 | 建议 |
|---|---|---|---|
| F1 | Codex 采集器 | 解析 sessions 目录，输出归一化用量事件（时间/工具/模型/项目/thread/tokens 明细） | 保留 |
| F2 | DeepSeek 采集器 | 解析 DSH 会话与 projcache，字段与 F1 同构 | 保留 |
| F3 | 增量与幂等 | 重复采集不重复计数；文件变更后只补新增 | 保留 |
| F4 | 本地存储 | 单文件 SQLite，可删可重建；采集失败不污染已有库 | 保留 |
| F5 | 成本估算 | 模型单价表可配置，算缓存折扣后的金额；未知模型单独列为 unknown 不计 0 | 保留 |
| F6 | 数据质量护栏 | 顶部显示"覆盖率/未识别模型/异常文件"，不静默丢数据 | 保留 |
| V1 | 总览卡片 | 今日 / 本周 / 本月 tokens、成本、会话数、活跃模型数 | 保留 |
| V2 | 用量时间序列 | 按天堆叠（缓存输入 / 未缓存输入 / 输出），可切周 | 保留 |
| V3 | Codex vs DeepSeek 对比 | 同一时间窗内 tokens / 成本 / 会话数并列与占比 | 保留 |
| V4 | 模型分布 | 环形图 + 每模型 tokens/成本表，点击筛选 | 保留 |
| V5 | 项目维度归因 | 按 cwd 聚合 top N，点击下钻到会话 | 保留 |
| V6 | 会话钻取 | 会话列表 → 单会话时间线，逐轮 tokens/成本 | 保留 |
| V7 | 缓存效率诊断 | 缓存命中率、低命中会话标红、"重复上下文浪费"估算 | 推荐 |
| V8 | 异常面板 | 单会话超阈值、单日成本突增、上下文膨胀提示 | 可选 |
| U1 | 筛选器 | 时间范围 / 工具 / 模型 / 项目，联动所有图表 | 保留 |
| U2 | 视觉质量 | 深浅主题、统一配色、空状态与加载态友好；截图即达到"能给别人看"的水准 | 保留 |
| U3 | 刷新 | 手动刷新 + 文件变更自动刷新（可选常驻） | 推荐 |
| U4 | 导出 | CSV（明细）与 PNG（当前视图） | 可选 |
| U5 | 隐私约束 | 只读本机路径，不读 `auth.json`/凭据，不上传任何数据 | 必须 |
| T1 | 形态 | 本地采集脚本（Python）+ 静态前端；无云服务、无账号 | 保留 |
| T2 | 一键启动 | `./run.sh` 拉起采集与服务，单端口访问 | 保留 |
| T3 | 测试 | 采集口径不变量测试（fixture 小样本）+ 金额计算测试；`pytest`/`unittest` 全绿 | 保留 |

## 2. 明确不做

- 云端多用户、账号体系、团队共享
- 读或展示任何 API key / token / 凭据
- 修改 Codex 或 DS Bot 的配置与数据
- 调用 DeepSeek 官方账单接口（无公开个人用量 API；如需历史账单只能手动导入）

## 3. 待用户拍板

1. 成本单价表：用公开价内置 / 你自己填 / 先只算 tokens 不算钱
2. 是否要常驻后台服务（开机自启、文件监听）
3. 视觉风格：清爽浅色为主 / 深色为主 / 跟随系统
4. DeepSeek 历史为空这件事：接受"从今天起积累" / 需要手动导入账单
